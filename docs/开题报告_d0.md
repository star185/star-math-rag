基于检索增强生成（RAG）的数学知识库智能问答系统的设计与实现

1  设计内容及要解决的主要问题

1.1  设计内容

本课题设计并实现一套基于检索增强生成（Retrieval-Augmented Generation，RAG）技术的数学知识库智能问答系统（Star Math）。系统以大学数学课程知识为领域背景，围绕知识库管理、语义检索、生成回答与交互展示的完整链路进行设计与实现，主要设计内容如下。

（1）领域知识库的构建与管理。将数学知识库语料（约110篇文档，涵盖概念、定理、反例与公式速查等知识卡片，按数学分析、线性代数、概率统计三大模块组织）整理为统一格式的扁平Markdown语料集；设计文档入库管线，实现文档上传、内容解析、父子分块切分、向量化、检索索引构建，以及文档更新、删除、全量重建与批量导入等知识库管理功能。

（2）语义检索与RAG问答核心。设计并实现混合检索与生成链路：对切分后的知识块构建本地向量索引与BM25关键词索引，通过互惠排名融合（Reciprocal Rank Fusion，RRF）融合两路检索结果；以子块检索、父块提供上下文的方式组装提示词，调用大语言模型生成带来源标注的回答；支持向量、关键词、混合三种检索模式与检索调试接口，并以Hit@1/3/5、MRR等指标对检索质量进行评测。

（3）Web交互系统。设计并实现基于浏览器的Web应用：包括用户登录鉴权（JWT）、RAG对话界面（流式输出、内联引文角标、来源卡片与分块预览）、知识库管理后台、检索测试页面、会话历史管理，以及支持真题训练的做题模块（出题、判分、解析、错题本）。

（4）评测与测试体系。构建用于系统验证的测试与评测体系：生成100道覆盖三大模块的数学测试题集（概念型、简答型、综合型、对比型），接入67道考研与高校数学真题；提供检索评测脚本、单题评测接口、评测记录存储与一键冒烟测试脚本，形成开发、评测、回归的闭环。

1.2  要解决的主要问题

（1）中文数学术语的检索召回问题。数学卡片正文以LaTeX公式为主，中文术语集中于标题，纯向量或纯关键词检索对什么是矩阵、什么是数列极限这类概念查询召回不足（初版混合检索Hit@1仅为0.43）。需设计面向数学语料的检索适配策略，包括标题精确命中加权、BM25标题命中优先、混合检索候选扩大等，使混合检索Hit@1提升至0.98。

（2）公式与概念混合内容的切分问题。数学知识块中定义、定理、公式与反例相互嵌套，简单定长切分易破坏语义完整性。需采用父子分块策略：按标题切分父块，超长父块再按段落与句子边界拆分子块，检索命中子块、生成时提供父块上下文，兼顾召回率与上下文完整性。

（3）生成内容幻觉与不可溯源问题。大模型直接作答可能脱离知识库产生幻觉，回答缺乏证据支撑。需通过检索增强约束生成范围，并在回答中以[n]引文角标关联来源卡片，实现回答可溯源、可核查。

（4）大模型接入的可用性与降级问题。LLM网关令牌存在有效期（约24小时），网关首字延迟波动较大，离线或未配置环境无法调用。需采用OpenAI兼容接口统一接入，并实现本地抽取模式与生成失败回退，保证系统在无外部大模型时仍可演示核心链路。

（5）交互体验中的流式响应问题。非流式生成单次请求约17秒且首字延迟接近总时长，用户体验差。需实现真流式SSE输出，通过异步事件循环与线程池推进生成器，将首字延迟降至秒级。

（6）系统的领域无关性与可复用问题。RAG核心管线应独立于具体领域，使系统可从已有领域平滑迁移到数学领域，验证文档解析、分块、检索、生成管线的通用性，为后续扩展其他学科知识库提供基础。

2  设计思路

2.1  总体架构

系统采用浏览器/服务器（B/S）架构，自底向上分为数据层、检索层、应用层与表现层。数据层以SQLite数据库存储文档元数据、知识块、会话与评测记录，以本地向量索引与BM25倒排索引支撑检索；检索层实现文档解析与父子分块、向量化与关键词索引构建、三种检索模式及RRF融合、相关性过滤与排序；应用层基于FastAPI提供REST与SSE接口，实现用户鉴权、知识库管理、RAG问答、检索调试、评测与做题等业务逻辑，大模型以OpenAI兼容接口经本地网关接入，未配置时回退本地抽取模式；表现层采用原生HTML、CSS、JavaScript前端，提供登录、对话、知识库、检索测试与做题等页面。

2.2  核心技术路线

系统的核心处理流程为：文档解析、父子分块、索引构建、混合检索、提示词组装、流式生成与引文溯源。文档解析阶段读取Markdown语料，按标题层级切分父块，超长父块按段落与句子边界拆分子块，并记录父子索引关系；索引构建阶段对子块经本地嵌入模型生成向量建立向量索引，同时用jieba分词构建BM25倒排索引；混合检索阶段将查询向量化后分别检索两路索引，经RRF公式融合候选结果，结合标题命中加权与相关性阈值过滤得到Top-K结果；生成与溯源阶段将检索块（子块与父块上下文）按序组装进提示词，流式调用大模型生成回答，回答中按来源顺序输出[n]引文，前端将引文绑定到来源卡片，支持点击查看原文与分块预览。

2.3  关键设计决策

一是本地优先。向量化与检索均在本机完成，不依赖外部向量数据库，降低部署与运行成本；大模型未配置时以本地抽取模式兜底，保证离线可演示。二是数学语料检索适配。针对术语在标题、公式在正文的语料分布特征，实施标题精确命中加权、BM25标题命中优先与混合候选扩大三项适配，实测将混合检索Hit@1从0.43提升至0.98。三是流式体验优化。大模型调用采用流式解析，SSE通道用异步生成器配合线程池逐帧推进，避免事件循环阻塞，实现逐字输出。四是安全与可维护。采用JWT鉴权、密码哈希存储，密钥在首次启动时自动生成并持久化；检索模式、分块参数等以配置项驱动，便于调参与扩展。

3  设计流程

3.1  开发模型

本课题采用结构化分阶段的开发流程，依次经过需求分析、概要设计、详细设计、编码实现、系统测试与文档交付六个阶段，每个阶段设置明确的输入、活动与产出，保证设计与实现的连贯性和可验证性。

3.2  主要阶段与产出

（1）需求分析：调研领域问答需求与同类RAG系统，明确功能与非功能需求，对应课题要求的领域文档与测试集、知识库管理、语义检索加RAG、Web界面、测试方案、大模型接入六项指标，形成需求说明。

（2）概要设计：确定B/S总体架构、模块划分与接口设计，形成架构设计文档。

（3）详细设计：设计文档解析与父子分块算法、混合检索与RRF融合流程、提示词组装与引文机制、数据库表结构，形成详细设计文档。

（4）编码实现：先后完成后端（配置、解析、向量库、检索、RAG、API）与前端（登录、对话、知识库、检索测试、做题）开发。

（5）系统测试：进行单元与接口测试、100题检索评测（Hit@1/3/5与MRR）、冒烟测试与前端功能联调，修复发现的问题。

（6）文档交付：编写使用说明与设计文档，整理测试数据与演示材料。
